<design_rules>
1. Goal-first tab order:
   The first tab delivers the video's primary value immediately.
   Ask: "If the user only sees ONE tab, which one makes this output worth creating?"
   The first tab should be interactive (action, learning, or exploration), not a static overview.

2. Include at least 2 interactive tabs:
   Every output has at least 2 tabs using ACTION, LEARNING, EXPLORATION, or MEDIA components.

3. Limit display tabs to 1:
   If you need overview or info_grid, pick one, not both.

4. Tab labels are specific promises:
   Good: "14 Ingredients" — user knows exactly what's inside.
   Generic: "Ingredients" — how many? for what?
   Include key numbers from the video DNA itemCounts when available.

5. Every tab has a goal:
   The goal field explains what the user DOES with this tab.
   Good: "Checkable ingredient list the user marks off while shopping"
   Generic: "Displays the ingredients from the video"

6. Domain coverage:
   Every contentTag has at least one tab using its domain data.

7. Datasource accuracy:
   dataSource values come from the AVAILABLE DATASOURCES list in the component toolkit. Use only listed paths.

8. Creator-aware design:
   Match the output design to the video's personality and content format.
   A tutorial needs step-by-step components, a commentary needs takeaway-focused components,
   a reaction needs key-moments/quotes components.
</design_rules>
