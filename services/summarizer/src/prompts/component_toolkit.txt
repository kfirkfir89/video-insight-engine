COMPONENT TOOLKIT — "Video to Action"
Every interactive must let the user DO something with the content:
follow steps, jump to a moment, memorize a card, run code, decide between options.
A component that only displays text is a fail mode — text walls belong in info_grid
ONLY when they are short reference cells, never long paragraphs.

ROUTING IS BY USER ACTION, NOT BY DOMAIN. checklist works for prerequisites (tech),
packing lists (travel), and ingredients (food). step_player works for setup guides (tech),
recipes (food), and itinerary planning (travel). Components are wayfinding by INTENT.

═══════════════════════════════════════════════════════════════════
DENSITY GATES (HARD RULES — assembler will drop tabs that violate)
═══════════════════════════════════════════════════════════════════

| Component         | min items | max items | max chars/cell                   |
|-------------------|-----------|-----------|----------------------------------|
| info_grid         | 3         | 20        | 120 chars per value (≈ 20 words) |
| flash_deck        | 3         | 15        | front ≤ 40, back ≤ 180           |
| comparison        | 3 rows    | 10        | each side ≤ 80 chars             |
| spot_explorer     | 2         | 25        | description ≤ 200                |
| step_player       | 3         | 25        | instruction ≤ 200                |
| moment_track      | 3         | 20        | label ≤ 60                       |
| quiz              | 2         | 8         | question ≤ 140                   |
| exercise_tracker  | 2         | 25        | name ≤ 40                        |
| checklist         | 3         | 30        | label ≤ 80                       |
| code_explorer     | 1         | 12        | explanation ≤ 200                |

If your extraction has fewer items than min: pick a DIFFERENT component or
fold the data into overview/info_grid. NEVER ship a 1-item spot_explorer or a
2-row comparison.

If a value would exceed max chars: split it into multiple shorter cells OR
move the long prose to spot_explorer (which has expandable descriptions).
NEVER pad info_grid cells with 40-word paragraphs — they collapse into a
wall of text on mobile.

═══════════════════════════════════════════════════════════════════
WHEN TO PICK EACH COMPONENT
═══════════════════════════════════════════════════════════════════

EXPLORATION — user browses and discovers:

  spot_explorer
    PICK WHEN: You have 2+ items each with a name AND a real description.
    SHIPS: Browsable cards with expandable detail, thumbnail (if frame
      available at item's timestamp), map/booking actions.
    GOOD FOR: Places (travel), products (review), phrases (language),
      key concepts (science), topics (any), gear/resources (tech).
    DATASOURCE: travel.itinerary, food.*, learning.keyPoints, science.concepts,
      language.phrases, review.alternatives.

  info_grid ⭐ THE REFERENCE TABLE — keep cells SHORT
    PICK WHEN: You have 3+ short reference rows that users LOOK UP, not READ.
    SHIPS: Searchable card grid (or table). Optional `evidence` field renders
      below the value in italic for sources/examples.
    GOOD FOR: Specs, glossary terms, credits, quick tips, ingredient swaps,
      key facts with sources.
    SHAPE: Each item = { key, value, evidence?, emoji? }. ALL fields short.
    NEVER USE FOR:
      • Definitions of complex concepts → use flash_deck instead
      • Step-by-step processes → use step_player
      • Comparisons with two sides → use comparison
      • Anything where the value runs longer than ~20 words

  code_explorer
    PICK WHEN: The video shows code, commands, or shell snippets on screen.
    SHIPS: Syntax-highlighted code with copy button, step-through navigation,
      and (when a frame is available) the on-screen code thumbnail beside it.
    SHAPE: { code, language, explanation, filename?, timestamp? }.

  comparison
    PICK WHEN: The video EXPLICITLY weighs Option A against Option B on the
      SAME criteria for at LEAST 3 features. Both sides must have substance.
    SHIPS: 3-column table (Feature / A / B) with winner highlighting + a
      pros/cons summary card.
    NEVER USE FOR:
      • Glossaries or term definitions ("X is when…")
      • Lists of N concepts the video introduces
      • Single-sided pros without a counterpart
      • Reviews where only one product is examined → use verdict-folded-into-overview
    DATASOURCE: review.comparisons, tech.cheatSheet (only when paired).

ACTION — user completes a task:

  checklist
    PICK WHEN: User physically checks items off in real life (shopping, packing).
    SHAPE: Array of items with label, optional amount/unit/group/note.

  step_player ⭐ ORDERED PROCESSES — the heart of "video to action"
    PICK WHEN: 3+ ordered steps. ALWAYS prefer step_player over a numbered list.
    SHIPS: Step-through guide with inline timer, tips, completion tracking,
      and a frame thumbnail per step (auto-attached when timestamp matches).
    GOOD FOR: Cooking, building, installing, assembling, setup, multi-stage
      processes in ANY domain.
    DATASOURCE: food.steps, project.steps, tech.setup, language.drills,
      science.experiments.

  exercise_tracker
    PICK WHEN: The video is a workout session with sets/reps/timer structure.
    SHIPS: Exercise cards with set tracking, rest timers, form cue expansion.

LEARNING — user tests understanding (LIMITED to learning + tech domains):

  quiz
    PICK WHEN: The user wants to verify what they retained.
    SHIPS: Scored multi-choice with explanations.
    DATASOURCE: ALWAYS enrichment.quiz.

  flash_deck
    PICK WHEN: 3+ concept-definition pairs the user would MEMORIZE.
    SHIPS: Flip cards with progress.
    NEVER USE FOR: tips, features, song analysis, chef tips, trivia, narrative
      moments. `front` must be a real term or concept name, never a category
      label like "chef_tip" or "pro_tip".
    DATASOURCE: enrichment.flashcards (preferred), learning.concepts (if at
      least 3 items have {name, definition} shape).

  scenario
    PICK WHEN: There are 2+ applied-knowledge "what would you do?" cases.
    SHIPS: Multi-choice with context and explanations.
    DATASOURCE: ALWAYS enrichment.scenarios.

MEDIA — user navigates the source video:

  moment_track ⭐ THE TIMELINE — frame-aware
    PICK WHEN: There are 3+ navigable points in the video worth jumping to.
    SHIPS: Vertical timeline where points (dots) and highlight spans (capsules)
      share one spine. Each expanded item shows a frame thumbnail + on-screen
      caption + OCR when the vision LLM extracted them — this is where the
      transcript and the frames fuse into a single artifact.
    SHAPE: items[] with { time, seconds, label } required; optional endSeconds,
      description, mood, emoji, speaker, tags. The assembler attaches
      thumbnailUrl, frameCaption, frameOcr, frameEvidence, frameSceneType
      automatically when frames are available.
    USE endSeconds ONLY for replayable highlights worth re-watching as a span
      (typical 15s–3min). OMIT endSeconds for navigation points.
    DATASOURCE: learning.timestamps, narrative.keyMoments, music.structure.
      YouTube chapters auto-fill as a fallback.

  lyrics_player
    PICK WHEN: Music video with lyrics + section structure.
    SHIPS: Section nav with synced lyrics.

DISPLAY — user reads (MAX 1 per output, last resort):

  verdict — Score + bottom line + best-for / not-for. Only for review-domain
    where the video reaches a single recommendation. Otherwise fold the
    conclusion into the overview hero.
  budget — Total + category breakdown + saving tips. Travel/finance only.

═══════════════════════════════════════════════════════════════════
ANTI-PATTERNS (the assembler will drop these — don't plan them)
═══════════════════════════════════════════════════════════════════

✗ info_grid with 2 items                → 3 minimum; otherwise use overview.
✗ comparison with 1 row, or with one    → at least 3 rows AND both sides
   side empty                              filled; otherwise route to info_grid.
✗ flash_deck for tips/features/trivia   → forbidden; use info_grid.
✗ gallery as a primary tab               → frames live INSIDE moment_track /
                                            step_player / code_explorer now.
                                            Standalone gallery is auto-appended
                                            ONLY when ≥10 high-quality vision
                                            captions exist.
✗ verdict for non-review domain          → verdict is review-only.
✗ Two tabs covering the same data        → pick one component per concept.
